Structured reasoning pilot

This pilot predates two fixes. It ran protocol v1. After reviewing it, Christian approved two changes before any scored run (protocol v2): a share of comparable cases must be given as a count, "k of n", which the code shrinks to (k+1)/(n+2) and flags when n is under 5, so "2 of 2" counts as 75%, not 100%; and the blind base-rate call (arm C) now also sees the question's background, still without the research. The pilot was not re-run; the numbers below are v1.

How to read the numbers

Base rate (p0)The starting point: how often things like this happen, before looking at this case. The model names 2–3 groups of comparable past cases (reference classes) and weights them; the code takes the weighted average.
Proportion vs rateA proportion is "share of comparable cases that ended YES". A rate is "n events per d days"; the code turns it into the chance of at least one event in this question's window: 1 − e−rate × window.
SourceR3 = research item 3 the bot had at the time; question = the question text; memory = the model's own knowledge.
Scenarios3–5 ways things could go, written before the drivers. Each has a chance of happening (sums to 100%) and a chance of YES if it happens. Route 1: the code adds up chance × chance of YES.
Drivers (×2 ↓, ×1.5 ↑ …)Facts about this case that move it away from the base rate. Each one multiplies the odds by a fixed step (×1.25, ×1.5, ×2, ×3, or divides). Route 2: the code applies them to p0, capped at ×10 in total. The waterfall shows each step in percentage points (pp); the same ×2 moves 20% to 33% (+13 pp) but 2% to 4% (+2 pp).
Routes and the final numberIf the two routes are within 10 pp (or a 1.5× odds factor), the final is their average (on the log-odds scale). If they disagree, the model's own final number is used, with its reason. The model's own number is shown either way.
Arm B vs arm CB: one call does everything. C: the base rate comes from a separate "blind" call that saw only the question, no news or background; the second call must start from it.
Modelsgpt-6.1-sol = frontier (on the tournament roster list); gpt-6-luna = the cheap model the live bot uses today. Both re-forecast the same stored live record with its original research and date.
